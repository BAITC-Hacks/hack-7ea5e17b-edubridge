# JelAI

Основной веб-интерфейс прогноза двух ветровых турбин на 24–48 часов. **JelAI = «жел» (ветер) + AI.** React, TypeScript, Vite и Recharts; серверный контракт команды сохранён. Альтернативный Python/Streamlit-интерфейс находится в `ui/app.py` и запускается через `ui/run.py`.

## Запуск

Из корня репозитория, с Node.js **24.14.0** и npm **11.9.0**:

```sh
cd ui/web
npm ci
npm run dev
```

Открыть **http://127.0.0.1:5173**. Сервер слушает только локальный адрес; если порт занят, запуск завершается ошибкой вместо выбора другого порта. Зависимости зафиксированы в `package-lock.json`.

По умолчанию включено **«Демо»**. Оно самостоятельно создаёт воспроизводимые синтетические кривые, имитирует шаги агента и предоставляет CSV. Реальная погода не загружается, модель не обучается, точность не измеряется. История живёт в текущей странице; обновление страницы сбрасывает её.

## API команды

В другом терминале, из корня репозитория:

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -e '.[dev,weather,model]'
.venv/bin/python -m wind_agent --config config/archive-model.json serve
```

Backend слушает `http://127.0.0.1:8000`. `config/archive-model.json` подключает обученный пакет `models/wind-power-v1` и архив NOAA GFS; первая загрузка погоды требует интернета. Начальный пример: **31 января 2026, 18:00 UTC**, обе турбины, 48 часов. Более ранний выпуск недопустим из-за cutoff production-модели. Запускать один процесс backend на каталог артефактов. Подробности — в [README платформы](../../README.md).

Синтетическая альтернатива без погодной сети — остановить текущий API и запустить:

```sh
.venv/bin/python -m wind_agent --config config/demo.json serve
```

`config/demo.json` возвращает fixture, а не реальный прогноз. [Model card](../../docs/model-card.md), [validation-отчёт](../../models/wind-power-v1/validation.json), [контракт оценки](../../docs/evaluation-api.md). Независимый январский holdout выбранной модели имеет MAE **0.226919**, wind-curve baseline — **0.209460**; baseline лучше. Эти ошибки относятся к `normalized_power`. Они не являются февральской точностью или независимой оценкой итогового production-refit.

В JelAI выбрать **«API»**. Адрес `/api` использует proxy Vite: `/api/health` перенаправляется на `http://127.0.0.1:8000/health`. В «Настройках подключения» можно проверить готовность backend. Для другого порта backend запустить Vite так:

```sh
WIND_API_TARGET=http://127.0.0.1:8001 npm run dev
```

Настройку также можно записать в локальный `.env.local` в этой папке и перезапустить Vite. Если в интерфейсе задан абсолютный URL вместо `/api`, браузер обращается к нему напрямую; backend должен разрешать этот origin через CORS. Сбой API отображается как ошибка и не подменяется демоданными.

Поддерживаются маршруты `GET /health`, `POST /runs`, `GET /runs/{id}`, `GET /runs/{id}/forecast`, `GET /runs/{id}/forecast.csv` и `GET /evaluation`. [Общий контракт](../../docs/api-contract.md).

Клиент проверяет принадлежность строк запуску и ревизии, почасовую сетку, турбины, горизонт, конечные числа, единицы и доступные временные границы. CSV должен соответствовать проверенному JSON; при расхождении экспорт недоступен. Эти проверки структуры не доказывают точность модели или корректность исходного архива.

`normalized_power` не означает MW/MWh. `fixture_dimensionless` принимается только с маркировкой fixture и отображается как демо-значение. Отсутствующие наблюдения и метрики не дорисовываются; показатели двух турбин не суммируются без подтверждённого масштаба.

## Сборка и проверки

Из `ui/web`:

```sh
npm test
npm run build
npm run preview
```

Сборка попадает в `dist`. Preview работает по **http://127.0.0.1:4173** и использует тот же proxy `/api` и `WIND_API_TARGET`. Это локальный просмотр, а не production-сервер.

При размещении `dist` на хостинге отдельно настроить HTTPS и reverse proxy `/api` → backend. Proxy из `vite.config.ts` работает только в dev/preview и не включается в статические файлы сборки.

Проверено 23 сентября 2026: **43 теста прошли**, production-сборка прошла без предупреждения о размере chunks. Браузерный вид проверен при **1440 × 1000** и **390 × 844**. На мобильном размере проверены главный блок, параметры и график; `scrollWidth=390` равен ширине viewport, горизонтального переполнения страницы нет. Через HTTP API выполнен fixture-запуск `4757020e27e0db0c3e1ba3ad`: выпуск `2026-02-02T00:00:00Z`, `turbine_2`, 24 часа, ревизия 1. Все 24 строки помечены `data_quality=fixture`. CSV скачан браузером, найден на диске и побайтово совпал с CSV backend.

Отдельно пройден реальный браузерный сценарий с backend **`6e4724e`**, `config/archive-model.json` и Python **3.11.16**; `pip check` прошёл. Выпуск `2026-01-31T18:00:00Z`, обе турбины, 48 часов: `run_id=3a6186ffff1b1dc52a5cf2cd`, `completed`, ревизия 1, 96 строк `normalized_power` с `data_quality=warning`. `/evaluation` вернул `ready`. CSV скачан браузером и побайтово совпал с backend; SHA256 `5c829ffc9a1dee16688298241cff1564188412d7d1f08a8536a46369597ed1a5`.

Архивная интеграция подтверждает выполнение модели, но не февральскую точность или независимую оценку production-refit. Проверки локальные, публичное размещение не выполнялось. Исторические 46 тестов Python/Streamlit не являются проверками React. [Протокол React с provenance](../../docs/demo.md#протокол-проверки-jelai-react--23-сентября-2026), [сценарий защиты](../../docs/pitch.md).
