# JelAI — демонстрация прогноза ВЭС

**JelAI** — «жел» (ветер) + AI. Основной интерфейс участника №3 теперь находится в `ui/web`: React, TypeScript и Vite. Он отображает почасовой прогноз, состояние агента и происхождение данных. [Инструкция frontend](../ui/web/README.md), [контракт API](api-contract.md), [README платформы](../README.md).

Прежний интерфейс Streamlit сохранён как альтернатива. Его HTTP-интеграция с backend `e5da2c6` проверена на синтетическом режиме, включая запуск из браузера. Backend объединён в `main` коммитом `903828a`. Исторический протокол ниже относится именно к Python/Streamlit: его результаты не переносятся автоматически на новый React-интерфейс. Реальный прогноз ВЭС с моделью и обновлением входов этими проверками не подтверждён.

Обновление `main` **`6e4724e`** содержит обученный пакет `models/wind-power-v1`, архивную конфигурацию и отчёт оценки. [Model card](model-card.md), [полный validation-отчёт](../models/wind-power-v1/validation.json), [контракт `/evaluation`](evaluation-api.md), [проверка replay](replay-validation.md). Состояние этих артефактов отделено от проверки нового React-интерфейса с обновлённым API.

## Основной запуск: React

Команды из корня репозитория. Окружение разработки: Node.js **24.14.0**, npm **11.9.0**; точные зависимости зафиксированы в `ui/web/package-lock.json`.

```sh
cd ui/web
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Встроенное **«Демо»** работает без backend и явно показывает синтетический пример. Переключатель **«API»** использует относительный адрес `/api`. Vite перенаправляет запросы на `http://127.0.0.1:8000`, удаляя префикс `/api`.

Если backend слушает другой адрес, настроить его до запуска Vite:

```sh
WIND_API_TARGET=http://127.0.0.1:8001 npm run dev
```

Для локального API запустить отдельный терминал в корне репозитория:

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -e '.[dev,weather,model]'
.venv/bin/python -m wind_agent --config config/archive-model.json serve
```

В интерфейсе выбрать **«API»**, открыть **«Настройки подключения»**, оставить `/api` и нажать **«Проверить»**. `config/archive-model.json` подключает обученную модель и архив NOAA GFS. Для первого выпуска выбрать **31 января 2026, 18:00 UTC**, обе турбины, 48 часов; более ранний момент не допускает production-cutoff модели. Первая загрузка погоды требует интернета. Один процесс backend должен писать в один каталог артефактов.

Для отдельной синтетической проверки остановить текущий API и запустить альтернативу:

```sh
.venv/bin/python -m wind_agent --config config/demo.json serve
```

Backend с `config/demo.json` синтетический; настоящее HTTP-соединение не делает fixture реальным прогнозом. При явном внешнем URL backend должен разрешать запросы из браузера через CORS. Для локальной разработки предпочтителен `/api` через proxy.

Проверка frontend и просмотр собранной версии из `ui/web`:

```sh
npm test
npm run build
npm run preview
```

Preview доступен по `http://127.0.0.1:4173`; для `/api` в нём действует тот же `WIND_API_TARGET`. Сборка создаёт `ui/web/dist`. На реальном хостинге требуется отдельно настроить reverse proxy `/api` → backend: файлы из `dist` не содержат сервер Vite или его proxy. Vite preview предназначен для локального просмотра сборки.

## Короткий показ JelAI

1. Назвать режим: встроенное синтетическое «Демо» либо «API» с указанием режима backend. Фоновая турбина — декоративная иллюстрация, а не фотография реального объекта и не телеметрия.
2. Выбрать дату выпуска, время UTC, одну или обе турбины и 24/48 часов. Нажать **«Рассчитать прогноз»**. Изменение формы само по себе не меняет уже показанный выпуск.
3. Показать доступные шаги агента, а под формой — фактические параметры результата, `run_id` и ревизию. **«Обновить статус»** повторно запрашивает состояние; это не новый расчёт.
4. На вкладке **«Прогноз»** объяснить график и таблицу. `valid_time` — конец часового интервала. Переключение UTC / Алматы меняет отображение времени, а не данные CSV. Индикатор полноты отражает наличие ожидаемых строк, а не точность модели.
5. Открыть **«Источник и качество»**: происхождение погоды, cutoff, предупреждения и полный журнал. На вкладке **«Оценка модели»** показывать только полученный отчёт; при его отсутствии метрики не выдумываются.
6. Нажать **«Скачать CSV»**, найти файл и сверить его с таблицей. API-экспорт проверяется на соответствие JSON; при расхождении скачивание недоступно. Повтор того же запроса выполняется кнопкой **«Рассчитать прогноз»** с теми же параметрами.

Во встроенном демо значения искусственные, единица — `normalized_power`. У backend fixture единица — `fixture_dimensionless`, на экране это **«Демо-значение»**. Нельзя называть эти значения MW/MWh или складывать показатели двух турбин без подтверждённого масштаба. Ошибка API не приводит к автоматическому переключению на демоданные.

В архивном режиме `/evaluation` читает отчёт поставленного пакета. По его независимому январскому holdout MAE выбранной модели — **0.226919**, wind-curve baseline — **0.209460**: более простая модель лучше на этом периоде. Это ошибки в `normalized_power`, а не проценты точности и не оценка февраля. Production-refit включает holdout в обучение и не имеет собственной независимой оценки. Предположения об исходных временных метках и нормализации описаны в model card.

Файлы бренда: [логотип SVG](../ui/web/public/assets/jelai-logo.svg), [знак SVG](../ui/web/public/assets/jelai-mark.svg). Авторский сгенерированный фон: [turbine-hero.png](../ui/web/public/assets/turbine-hero.png); происхождение и точный запрос сохранены в [hero-prompt.txt](../ui/web/public/assets/hero-prompt.txt). SVG можно скачать из окна «Подключение и бренд».

## Альтернативный запуск: Streamlit

Выполнять из корня рабочей папки UI. Команды используют `python3` и создают отдельное окружение внутри `ui/`; они не устанавливают и не запускают API. Проверенные версии: UI — Python 3.14.3, backend — Python 3.11.16. Используйте для backend отдельное окружение Python 3.11.

```sh
python3 -m venv ui/.venv
ui/.venv/bin/python -m pip install -r ui/requirements.txt
ui/.venv/bin/python ui/run.py
```

Запускатель применяет тему интерфейса, отключает телеметрию Streamlit и по умолчанию слушает только 127.0.0.1. Также поддерживается обычный запуск `ui/.venv/bin/python -m streamlit run ui/app.py` с темой Streamlit по умолчанию.

Открыть адрес, который Streamlit напечатает в терминале, обычно `http://localhost:8501`. В боковой панели выбрать «Режим»: «Демо» или «API». В «Демо» начальный пример уже показан и явно обозначен как синтетический.

Настройки подключения перед запуском:

```sh
export WIND_API_BASE_URL=http://127.0.0.1:8000
export WIND_API_TIMEOUT=10
ui/.venv/bin/python ui/run.py
```

`WIND_API_TIMEOUT` задаётся в секундах и ограничивает ожидание отдельного HTTP-запроса; это не предельная длительность всего расчёта. Для встроенного деморежима UI API не требуется.

Для воспроизведения HTTP-интеграции выполните следующие команды из корня репозитория с включённым backend (`main` от `903828a` или эта рабочая ветка). Окружение `.venv` для backend отделено от `ui/.venv`. При использовании отдельной рабочей папки backend проверенный исходный commit — `e5da2c6`; переключать ветку работающего UI не требуется.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m wind_agent --config config/demo.json serve
```

Этот сервис слушает `http://127.0.0.1:8000`, OpenAPI доступен по `/docs`. В UI выберите «API», укажите этот адрес и нажмите «Проверить подключение». `config/demo.json` запускает **синтетический backend**, для него не нужны GRIB-зависимости или обученная модель. Запускайте один процесс backend на каталог артефактов. Команды архивного режима и его незаполненные требования к модели описаны в README платформы.

## Два режима

| Режим | Что показывает | Что доказывает |
| --- | --- | --- |
| «Демо» в UI | Встроенные искусственные строки с `target_unit=normalized_power` и журнал | Работу экранов, выбора параметров, графика, таблицы и экспорта |
| «API» → backend `config/demo.json` | Ответы HTTP-сервиса: постоянное `0.5`, `target_unit=fixture_dimensionless`, `data_quality=fixture`, предупреждение `SYNTHETIC FIXTURE` | Проверенную HTTP-интеграцию и цикл платформы на fixture; не точность ML |
| «API» → backend архивного режима | Результат сервиса при готовых реальных входах и модели | Только фактически выполненный расчёт; качество и происхождение оцениваются по его артефактам |

Оба синтетических источника должны быть явно обозначены на экране и в экспортируемых данных. Их числа не являются прогнозом реальной ВЭС, измерениями, результатом обучения или подтверждением точности. `fixture_dimensionless` означает тестовую безразмерную величину; её нельзя переименовывать в нормализованную мощность. При ошибке API интерфейс не переходит в деморежим автоматически. Режим API означает подключение по HTTP и сам по себе не подтверждает реальность прогноза или историческую допустимость погоды: нужно проверить metadata и исходные артефакты сервиса.

## Короткий показ Streamlit: 3–4 минуты

1. **Контекст, 20 секунд.** «Это интерфейс для почасового прогноза двух турбин на 24–48 часов. Сейчас показываем явно обозначенное синтетическое демо интерфейса». При подключении backend назвать режим API, конфигурацию `demo` или `archive` и конкретный `run_id`. Для backend demo прямо сказать: «Это синтетический расчёт через настоящий HTTP API».
2. **Параметры, 30 секунд.** Выбрать «Дата исторического выпуска», «Время выпуска (UTC)», одну или обе «Турбины» и «Горизонт» 24 часа. Время выпуска вводится в UTC; «Часовой пояс графика» переключает отображение между UTC и Asia/Almaty. Согласованный пример backend: 31 января 2026, 18:00 UTC / 23:00 Asia/Almaty. `valid_time` — конец интервала `[valid_time−1h, valid_time)`, первый результат имеет lead `+1h`. Это соглашение API не подтверждает временную семантику исходной истории SCADA.
3. **Расчёт и результат, 60 секунд.** Нажать «Рассчитать прогноз»; показать `run_id`, состояние и доступные шаги агента. В режиме API состояние можно запросить кнопкой «Обновить статус». После завершения открыть вкладку «Прогноз» с графиком и таблицей. Объяснить ось времени и фактический `target_unit`: в backend demo это `fixture_dimensionless`, во встроенном демо — `normalized_power`. Ни одна из этих величин не равна MW или MWh; значения разных турбин не складываются без подтверждённого масштаба.
4. **Проверяемость, 40 секунд.** На вкладке «Источник и качество» найти `issue_time`, `revision`, `weather_run_time`, `weather_model`, `training_cutoff`, `model_version`, предупреждения и качество данных. Если API передал метаданные публикации погоды, отдельно показать `forecast_available_at` и основание доступности. Время инициализации погоды не заменяет время её публикации.
5. **Другой горизонт, 30 секунд.** Выбрать 48 часов и выполнить новый запуск. Убедиться, что новый результат соответствует выбранным параметрам; изменение полей формы само по себе не пересчитывает ранее полученный прогноз.
6. **Экспорт, 20 секунд.** Скачать CSV и открыть его. Сверить выбранные турбины, временные метки, единицы, идентификатор запуска и ревизию с экраном. В деморежиме сохранить маркировку синтетического происхождения.

Не показывать синтетическую линию «фактическая выработка». Если февральский факт не предоставлен, сравнение с ним и test-метрики отсутствуют. На вкладке «Оценка модели» validation-метрики допустимы только с границами периода, единицами и сопоставимым baseline из отчёта участника №2.

## Сбои и пересчёт Streamlit

| Проверка | Действие | Ожидаемый результат |
| --- | --- | --- |
| Сервис недоступен | В режиме API указать локальный адрес без запущенного сервиса и нажать «Проверить подключение» или выполнить расчёт | Понятная ошибка подключения; нет синтетической подстановки и ложного успешного результата |
| Timeout | На тестовом API задержать ответ дольше `WIND_API_TIMEOUT` | Понятная ошибка ожидания; пользователь может повторить запрос |
| Ошибка агента | Получить статус `failed` с причиной от тестового или реального API | Видны состояние, причина и доступный журнал; прогноз не объявлен завершённым |
| Пустой прогноз | Вернуть завершённый запуск с пустым массивом прогноза | Явное сообщение об отсутствии данных; пустота не превращается в нулевую выработку |
| Повтор того же запроса | Нажать «Повторить расчёт» на интегрированном backend | При тех же входах backend сохраняет `run_id` и ревизию; сверить с предыдущим результатом |
| Обновление входов | Участник №1 подаёт новые допустимые на момент расчёта входы; получить обновлённое состояние запуска | UI показывает возвращённую ревизию, причину пересчёта и соответствующий прогноз; прошлый результат не выдают за новый |

В режиме «Демо» кнопка «Повторить расчёт» показывает искусственную следующую ревизию для демонстрации UI. Погода и модель при этом не обновляются. Последние два сценария таблицы проверяют совместную работу UI и backend. В режиме API ревизию определяет backend; UI не доказывает его идемпотентность или отсутствие утечки данных. Отдельного API-маршрута для принудительного пересчёта в исходном плане нет; способ инициирования обновления согласуется с участником №1.

## Контракт и исторический статус HTTP-интеграции Streamlit

Маршруты реализованы в backend `e5da2c6`. Сквозная проверка UI → HTTP API → backend demo пройдена. Дополнительно API-клиент проверен через настоящий HTTP для всех шести сочетаний турбин и горизонтов. Это проверки без модели ВЭС; они не заменяют проверку реального архивного прогноза. Доступны:

- `GET /health` — готовность сервиса;
- `POST /runs` — ответ 202, приём `issue_time`, `horizon_hours`, `turbine_ids` и возврат `run_id`, `status`;
- `GET /runs/{run_id}` — состояние, `events`, `warnings`, `error`, `revision`, `recalculation_reason`;
- `GET /runs/{run_id}/forecast` — массив почасовых записей общего контракта;
- `GET /evaluation` — сейчас `unavailable`; валидация и baseline появятся после интеграции отчёта модели.

Журнал backend находится в `events`, каждое событие содержит `at`, `step`, `message`, `details`. UI должен показывать эти события и предупреждение `SYNTHETIC FIXTURE`, даже если ответ не содержит дополнительного поля `source_mode`. Приём POST не означает успешного расчёта: получить `completed` перед загрузкой прогноза; `failed` сопровождается `error`. До завершения `/forecast` и `/forecast.csv` возвращают 409, неизвестный `run_id` — 404, некорректный запрос — 422.

`GET /runs/{run_id}/forecast.csv` предусмотрен общим контрактом. UI скачивает CSV именно с этого маршрута и проверяет совпадение строк, мощности, run_id, revision и временных меток с проверенным JSON-прогнозом. При отсутствии маршрута или несовпадении экспорта показывается ошибка; другой CSV незаметно не подставляется.

UI отправляет идентификаторы `turbine_1` и `turbine_2` для подписей «Турбина 1» и «Турбина 2»; они должны совпадать с конфигурацией backend. Зафиксировать успешный `run_id`, версию сервиса, его режим и результат проверки. Раздельно отмечать HTTP-интеграцию на backend fixture и расчёт реального прогноза ВЭС.

Таблица происхождения дополняет отсутствующие поля из `events.details.weather_provenance`, только когда совпадают турбина, погодная модель и время её выпуска. Данные строк имеют приоритет. Наличие metadata в таблице само по себе не подтверждает историческую доступность; исходные артефакты остаются основанием проверки. Этот путь проверен на фактическом ответе backend demo для обеих турбин.
