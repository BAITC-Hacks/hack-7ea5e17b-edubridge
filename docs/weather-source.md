# Архив оперативных прогнозов погоды

Источник MVP — **NOAA GFS 0.25° в публичном AWS Open Data bucket** `noaa-gfs-bdp-pds`. Доступ без ключа и аккаунта. Это архив оперативной модели: [описание NOAA/AWS](https://registry.opendata.aws/noaa-gfs-bdp-pds/) и [каталог продуктов NCEP](https://www.nco.ncep.noaa.gov/pmb/products/gfs/). NOAA просит указывать источник; обработанные нами значения не выдаются за неизменённый оригинальный продукт NOAA.

Проверка 23 сентября 2026 дала реальные HTTP 200 для индексов и HTTP 206 для выбранных GRIB-сообщений начала, середины и конца февраля. Полный горизонт 48 часов за `issue_time=2026-01-31T18:00:00Z` скачан и декодирован для обеих турбин: 96 записей. Это проверка погодного входа, а не прогноз выработки или доказательство качества модели №2. Компактные квитанции с URL, SHA256, ETag, LastModified, HTTP-статусами, выбранной ячейкой и сводкой всех 29 ежедневных выпусков находятся в [evidence/weather-probe.json](evidence/weather-probe.json).

Адаптер выбирает ближайшую точку сетки. Для обеих координат это **43.75°N, 78.50°E**; расстояние около 12 км. Поэтому метеопризнаки турбин совпадают: разрешение GFS не позволяет заявлять различия погоды между столь близкими турбинами. Исходные координаты и выбранная точка сохраняются отдельно в provenance.

Из `gfs.tCCz.pgrb2.0p25.fFFF` берутся мгновенные `UGRD` и `VGRD` на 100 м и `TMP` на 2 м. Ветер = `hypot(U,V)` в м/с, температура переводится из K в °C. Высота ветра — **100 м над землёй**, а не подтверждённая высота ступицы. Эти признаки требуют согласования с моделью №2; нельзя незаметно смешивать 10-метровый и 100-метровый ветер. Данные почасовые, временная интерполяция не используется.

Внутренний контракт мощности использует `timestamp_semantics=hour_end`: timestamp обозначает конец часового интервала. Погодные признаки при этом имеют **`feature_time_basis=instant_at_end`**: берётся нативное мгновенное поле GFS в этот момент, а не среднее за предыдущий час. `valid_time` не сдвигается, значения не усредняются. Эта разница должна быть отражена в metadata модели №2; исторический смысл времён исходного датасета ВЭС ещё должен быть подтверждён его аудитом.

## Время доступности

`model_run_time` берётся из цикла модели и проверяется внутри каждого GRIB. Он не считается временем публикации. Для полного запрошенного горизонта адаптер получает S3 listing и выбирает самый поздний цикл, для которого **каждый** необходимый GRIB и каждый его `.idx` существуют и имеют допустимые метаданные. `forecast_available_at` — максимум `LastModified` этих объектов. Все времена UTC; целевые часы — `issue_time+1h` … `issue_time+horizon`.

[AWS определяет LastModified как время изменения/создания объекта](https://docs.aws.amazon.com/AmazonS3/latest/API/API_Object.html). Это свидетельство по объектам архива, **не точное время исходной публикации NOAA** и не сегодняшний `retrieved_at`. История прав доступа bucket отдельно не восстановлена. Мы используем архив NOAA, предназначенный для публичного распространения, и честно сохраняем это основание в `availability_basis` и `availability_evidence`.

Существенное исключение: для multipart upload `LastModified` может означать **начало**, а не завершение загрузки ([AWS metadata](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingMetadata.html)). Поэтому такие объекты не допускаются: требуется обычный ETag из 32 hex-символов в кавычках; multipart ETag имеет суффикс `-N`, как описано в [AWS checksum documentation](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html). Это проверяется для всех GRIB и индексов, а не только одного образца. Все 2 784 объекта, необходимые для проверенных 29 выпусков с горизонтом 48 часов, прошли этот фильтр. ETag используется как идентификатор версии; он не объявляется SHA256 или универсальным MD5.

Каждый GET индекса или GRIB защищён `If-Match`; ответ обязан повторять ETag и LastModified из listing. Для GRIB проверяются HTTP 206, точный Content-Range, длина и встроенные run/valid time, параметр, уровень, единицы и мгновенный тип поля. Более поздний или неполный выпуск отклоняется; ищется предыдущий допустимый цикл, максимум на 48 часов назад. Если допустимого полного выпуска нет, получается ошибка. Фактическая погода, reanalysis, analysis `f000` и незаметная замена на более поздний forecast не используются.

Метаданные проверены для всех 29 выпусков от 31 января до 28 февраля включительно, в 18:00 UTC (23:00 Asia/Almaty). Для каждого найдены все 96 объектов 48-часового горизонта. Дополнительный выпуск 28 февраля нужен при `hour_end`, чтобы 24-часовой replay также включал конец последнего интервала февраля — **1 марта 00:00 Asia/Almaty**. Февральские интервалы выбираются по `2026-02-01 00:00 < valid_time <= 2026-03-01 00:00` в этой зоне: 672 часа на одну цель. Остальные мартовские интервалы сохраняются отдельно. Это **аудит наличия и временных метаданных**; полная загрузка всех февральских GRIB и расчёт выработки за месяц этим утверждением не подменяются.

## Воспроизведение и cache

После установки проекта:

```sh
python -m pip install -e ".[weather]"
python scripts/probe_weather.py
python scripts/probe_weather.py --dates 2026-02-01 2026-02-14 2026-02-28 --sample-fields --output artifacts/weather-probe-samples.json
python scripts/probe_weather.py --february --output artifacts/weather-probe-february.json
python scripts/probe_weather.py --dates 2026-01-31 --horizon 48 --fetch --output artifacts/weather-probe-full.json
```

`eccodes==2.44.0` проверен на Windows x64, Python 3.11: wheel установился через pip, реальные сообщения GRIB декодируются. [ECMWF описывает поставку бинарной библиотеки в пакете](https://pypi.org/project/eccodes/2.44.0/). Другой ОС потребуется собственная проверка запуска.

`artifacts/weather-cache/raw/<sha256>.bin` хранит точные тела HTTP-ответов (listing XML, индексы и выбранные GRIB-сообщения) и объединённые GRIB-сообщения каждого часа. `requests/*.json` сохраняет URL, Range/If-Match, HTTP-статус, заголовки, время получения и SHA256. `extractions/<sha256>.json` — неизменяемые манифесты состава извлечения; `source_request` ссылается на них, `raw_sha256` соответствует сохранённому GRIB-набору. Порядок объединения полей фиксирован: `t2m,u100,v100`.

SHA256 cache проверяется при чтении. Индексы и поля повторно используются только по тому же URL/Range/ETag; listing обновляется для обнаружения изменений. `offline=True` в конструкторе разрешает только ранее сохранённые запросы и не скрывает промах cache. Timeout по умолчанию 30 секунд, максимум три попытки для сетевых ошибок/408/429/выбранных 5xx, до четырёх одновременных загрузок. Большой cache не включён в Git; повторная загрузка публична и воспроизводима. Native hourly 48h требует порядка 130 МБ сетевых данных и примерно вдвое больше диска из-за сохранения отдельных сообщений и наборов.

## Отвергнутые подмены

Open-Meteo Single Runs за нужный период не выбран из-за отмеченного в плане вопроса о hindcast-происхождении. Historical Weather/reanalysis и сшитые первые часы разных запусков не заменяют исторический оперативный выпуск. NCEI остаётся возможным резервным источником, но текущий адаптер не переключается на него без отдельной проверки происхождения, времён и схемы.
