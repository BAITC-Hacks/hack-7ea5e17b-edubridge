# Проверка исторического replay февраля 2026

Replay использует реальную обученную модель `models/wind-power-v1` и оперативный архив NOAA GFS через адаптер участника №1. Выпуски формируются за 29 ежедневных исторических моментов: 31 января–28 февраля 2026, в 23:00 `Asia/Almaty` (18:00 UTC), для обеих турбин и полного горизонта 48 часов.

**Результат проверки 23 сентября 2026: PASSED.** Завершены 29/29 выпусков, сохранены 2 784 строки полных прогнозов; выбраны 1 344 февральские строки, по 672 на турбину, без пропусков. Независимо перечитаны и проверены SHA256 всех 1 392 raw-наборов погоды (3 868 416 520 байт). Повтор январского выпуска сохранил ревизию 1. Итоговые JSON и CSV доступны по ссылкам ниже; фактическая февральская точность не оценивалась.

Статус полного расчёта и его независимой проверки фиксируется в [evidence/february-replay.json](evidence/february-replay.json). Скрипт формирует этот файл только после успешного завершения всех выпусков и проверок. Отсутствие файла либо `status`, отличный от `passed`, не означает успешный replay.

## Воспроизведение

Из корня репозитория, после установки зависимостей:

```sh
python -m pip install -e ".[dev,weather,model]"
python scripts/verify_february_replay.py --smoke-only --horizon 48
python scripts/verify_february_replay.py --horizon 48
```

Первая команда проверки исполняет настоящий январский выпуск, 96 записей для двух турбин. Основная команда вызывает `AgentService.replay(48)` с [config/replay-february.json](../config/replay-february.json). Обёртка над `service.run` выводит начало, завершение, статус и длительность каждого выпуска; она не меняет входы, числа модели, выбор погоды или правило пересечений. Неуспешный или неполный replay не проходит независимый аудит; никаких фиктивных строк не создаётся.

Погодный cache — `artifacts/weather-cache`. Выпуски и ревизии сохраняются в `artifacts/february-integration/archive/runs`, выбранные февральские часы — в `artifacts/february-integration/archive/replay/2026-02-48h`. Отдельный каталог не смешивает исторический пакет с текущими запусками API. Первая загрузка месяца требует нескольких гигабайт сети и диска; повторная использует проверяемый cache.

Выбранный февральский результат дополнительно экспортируется в [JSON](../outputs/forecast/february-2026-48h.json) и [CSV](../outputs/forecast/february-2026-48h.csv). Эти компактные файлы включаются в Git и содержат реальные прогнозы обеих турбин; большие исходные GRIB остаются в ignored cache. Их SHA256 записываются в evidence.

Эквивалентный запуск движка без отдельного аудитора:

```sh
python -m wind_agent --config config/replay-february.json replay --horizon-hours 48
```

Проверка уже сохранённых результатов без запросов погоды и вызовов модели:

```sh
python scripts/verify_february_replay.py --verify-only --horizon 48 --export-dir outputs/forecast
```

## Что проверяется

- Все 29 выпусков завершены; каждый содержит 48 последовательных часов для каждой турбины, всего **2 784** записи полных прогнозов и столько же погодных записей.
- Все значения конечны, `(turbine_id, valid_time)` уникальны внутри выпуска, часы соответствуют `issue_time+1h` … `issue_time+48h`.
- Для каждой строки `model_run_time <= forecast_available_at <= issue_time`, `training_cutoff <= issue_time`; cutoff выбора модели и калибровки не позднее training cutoff. Версия модели и погодный цикл совпадают с сохранёнными входами. Источником является оперативный архив, а не fixture или фактическая погода. Проверяется документированное основание доступности single-part объектов.
- Внутри горизонта используется один GFS run; его raw SHA256-наборы сохранены в cache. Оба объекта используют ближайшую ячейку **43.75°N, 78.50°E**. Наличие одной ячейки не выдаётся за независимые локальные метеонаблюдения.
- Для каждого часа февраля независимо повторяется заранее выбранное правило: побеждает самый поздний допустимый `issue_time`; сравнение с фактической ошибкой не участвует в выборе.
- Получается ровно **672 часовых интервала на турбину**, **1 344 строки** выбранного прогноза. При `hour_end` локальная граница выбора: `2026-02-01 00:00 < valid_time <= 2026-03-01 00:00`. Последний интервал февраля заканчивается 1 марта в 00:00, поэтому выпуск 28 февраля сохранён. Пересекающиеся горизонты и остальные часы марта остаются в своих выпусках.

Evidence содержит SHA256 исходных файлов прогнозов, погоды и входов каждого выпуска, SHA256 модели, временные границы, число строк, выбранные ячейки и SHA256 JSON/CSV-экспорта. Аудитор дополнительно перечитывает каждый уникальный raw-набор погоды и сверяет содержимое с его SHA256. JSON/CSV содержат одинаковые поля контракта; список `warnings` в CSV записан JSON-строкой. Эти контрольные суммы подтверждают конкретный результат запуска; время сегодняшнего скачивания погоды не считается исторической публикацией.

## Ограничения результата

Это проверка работоспособности и согласованности времён **при явно указанных предположениях**, а не доказательство февральской точности. Фактическая выработка февраля не предоставлена, поэтому февральские MAE/RMSE отсутствуют.

Пакет модели предполагает фиксированный UTC+5 (`Etc/GMT-5`) для исходного SCADA, отметку начала десятиминутного среднего и нулевую задержку публикации. Эти условия и нормализация мощности не подтверждены организатором; предупреждения модели сохраняются в каждой строке. Выходная единица — `normalized_power`, без перевода в MW/MWh и без необоснованного сложения турбин в мощность станции. Интервалы неопределённости не калиброваны.

Цель использует `hour_end`, погодный признак — мгновенное значение GFS на конце интервала (`instant_at_end`), не среднее за час. Нативные погодные времена не сдвигаются. Доступность погоды обоснована metadata объектов архива; исходное время публикации NOAA и исторические ACL bucket полностью не восстановлены. Подробности: [weather-source.md](weather-source.md) и [model-card.md](model-card.md).
