# API участника №1 → интерфейс участника №3

API запускается из корня репозитория после установки зависимостей:

```sh
python -m wind_agent --config config/demo.json serve
```

Это **синтетический demo**, не реальный прогноз выработки. Для готовой модели
использовать `--config config/archive-model.json`; готовность проверять через `/health`.
Общий запуск API и UI: `python scripts/run_app.py`. Шаблон `config/archive.json`
предназначен для отдельного погодного fetch или подключения другого пакета модели.
Без конфигурации включается архивный режим. `WIND_AGENT_CONFIG` задаёт путь по
умолчанию; явный `--config` имеет приоритет. Один процесс / worker: очередь MVP
выполняется внутри процесса. Перезапуск процесса прерывает незавершённую задачу.

OpenAPI: `http://127.0.0.1:8000/docs`. Фабрика для ASGI:
`uvicorn wind_agent.api.app:default_app --factory --workers 1`.

`/evaluation` в архивном режиме читает `validation.json` настроенного пакета и
проверяет его связь с metadata и SHA256 весов. Статусы: `ready`, `unavailable`,
`invalid`. Tuning, holdout и production refit разделены; февральский факт отсутствует.
Формат и ограничения: [evaluation-api.md](evaluation-api.md).

| Метод | Путь | Успешный ответ |
| --- | --- | --- |
| GET | `/health` | 200: готовность сервиса и входов, режим |
| POST | `/runs` | 202: `{ "run_id": "...", "status": "queued" }` |
| GET | `/runs/{run_id}` | 200: запрос, статус, ревизия, события, предупреждения, ошибка |
| GET | `/runs/{run_id}/forecast` | 200: JSON-массив `ForecastRecord` |
| GET | `/runs/{run_id}/forecast.csv` | 200: CSV тех же записей |
| GET | `/evaluation` | 200: доступность метрик и факта, ограничения оценки |

Пример тела `POST /runs`:

```json
{
  "issue_time": "2026-01-31T18:00:00Z",
  "horizon_hours": 24,
  "turbine_ids": ["turbine_1", "turbine_2"]
}
```

Идентификаторы должны совпадать с конфигурацией. `issue_time` обязан содержать
часовой пояс; внутри сервиса он приводится к UTC. `horizon_hours`: только 24 или
48. Время без offset и неверный запрос возвращают 422.

`valid_time` обозначает **конец** прогнозируемого часового интервала:
запись с `valid_time=2026-02-01T01:00:00+05:00` относится к интервалу
`[2026-02-01T00:00:00+05:00, 2026-02-01T01:00:00+05:00)`.
Первый результат имеет `valid_time = issue_time + 1h`. Отображать это время
как начало часа нельзя; timezone исходной истории подтверждается отдельно.

После 202 опрашивать `/runs/{run_id}`. Состояния:
`queued` → `fetching_weather` → `validating` → `forecasting` → `analysing` →
`completed`; при ошибке — `failed` с объяснением в `error`. UI показывает события
`events`, `warnings` и `recalculation_reason`, включая ограничения demo и источника
погоды. Ошибка вычисления хранится в записи запуска: успешный POST не означает
успешный прогноз.

Несуществующий запуск возвращает 404. Попытка скачать прогноз до успешного
завершения возвращает 409, включая failed-запуски. Тело ошибки:
`{ "detail": "объяснение" }` (валидационные ошибки FastAPI содержат список в
`detail`).

Поля результата определены в `wind_agent.contracts.ForecastRecord` и доступны
в OpenAPI. JSON и CSV содержат одинаковые поля: версия схемы, ID и ревизия,
время выпуска/целевого часа, ID турбины, горизонт, прогноз и его единицы,
погодная модель/выпуск, версия модели выработки/cutoff, качество и предупреждения.
В CSV списки и объекты сериализуются как JSON, отсутствующие значения — пустая
ячейка. `warnings` читать через JSON parser, а не разделять по запятым.
Нормализованные значения нельзя обозначать как MW/MWh или суммировать между
турбинами без подтверждённого масштаба.

CLI для синтетического цикла:

```sh
python -m wind_agent --config config/demo.json health
python -m wind_agent --config config/demo.json run --issue-time 2026-01-31T18:00:00Z --horizon-hours 24
python -m wind_agent --config config/demo.json replay --horizon-hours 48
```

`run` и `replay` выводят JSON. Exit code 0 — выполненный цикл, 1 — failed/partial
результат, 2 — ошибка аргументов/конфигурации. Успех demo подтверждает работу
платформы, но не качество ML или реальное архивное покрытие февраля.

Replay выпускает 29 расчётов, с 31 января по 28 февраля в 23:00 Asia/Almaty.
Итоговая февральская таблица содержит интервалы с концами строго после начала
1 февраля и до 00:00 1 марта включительно: 672 часа на турбину, 1344 записи.

Реальный архив погоды можно загрузить независимо от готовности ML:

```sh
python -m wind_agent --config config/archive.json weather-fetch --issue-time 2026-01-31T18:00:00Z --horizon-hours 24 --output artifacts/weather-fetch.json
```

Команда допускает только архивный режим `gfs_s3`. JSON содержит запрос и массив
`records` с полным provenance каждой погодной записи; исходные ответы и их
контрольные суммы сохраняются в `cache_dir`. Статус успешной загрузки погоды не
означает, что модель выработки обучена или готова.
